# Feedback Loop Analysis — 2026-07-16

Agent version: 6.3.0 (current). Cohort under study forecast by v6.0.0 (n=45) and v6.2.0 (n=12).

Focus: the **MiniBench 06/29 cohort** (`minibench-2026-06-29`, post IDs 44298–44357, 60 questions),
which the user flagged as a poor-performing batch. Compared against the prior cohort
(`minibench-2026-06-15`, 44050–44109) forecast under v5.0.0.

## TL;DR

1. **The regression is real and ~40%, not a field artifact.** Every metric — peer (field-relative),
   baseline (absolute), and Brier (absolute) — dropped by roughly the same fraction between the
   two cohorts. If it were just harder questions, peer score would hold; it didn't.
2. **The failure mode is NOT lost grounding.** The user's leading hypothesis (research sub-agent
   returns condensed summaries → orchestrator less grounded) is **refuted** by all four
   catastrophic-miss autopsies. In every case the correct signal was in the orchestrator's own
   context.
3. **The failure mode is a reasoning/weighting pathology:** status-quo bias + overconfident
   (under-dispersed) tails. In 3 of 4 worst misses, the premortem step *literally wrote the correct
   answer*, then the agent dismissed it and kept its overconfident number.
4. **The premortem gate is toothless** — "warn" verdicts don't block, and it auto-approves after
   3 fails. Nothing forces the estimate to move toward the counterargument it generated.
5. **Model-vs-architecture is confounded** and not cleanly separable from two cohorts. A decisive
   same-question retrodict experiment is proposed.

### 44300 — NIFC National Preparedness Level → PL4
- Research sub-agent **never invoked** ("No such tool available" — the v6.0.0 bug fixed in v6.1.0);

  "not comparable" and conditioned the base rate *down* (19% → 12–15%).
- Its own premortem wrote: *"escalation by ~July 7-9 is quite plausible… arguing for 30-35% rather
  than 21%."* Dismissed.
- Counterfactual: treat the early-PL3/above-normal fingerprint as the 2012/2021 pattern → ~40%.

### 44303 — Russia producer-inclusive diesel export ban

### 44339 — West Vancouver Island drought level (MC), log score 3.22

### 44352 — Moscow Kapotnya refinery struck (v6.2.0 data point)

## The unifying pattern

All four (and the tail generally) share one shape:

> **The agent surfaces the correct, higher-uncertainty answer somewhere in its own reasoning —
> usually in the premortem/counterargument — and then discards it in favor of an overconfident
> anchor.** The adversarial step is generative but not corrective.

This is compatible with the ~40% degradation being a *model behavior* difference (Opus 4.8 anchoring
harder on its first estimate and rationalizing past its own counterargument), but the data cannot
isolate that from question difficulty or the v6.0.0 research bug. What is clear is that the
**correction machinery is the highest-leverage fix regardless of model**: the same fix helps 4.6, 4.8,
and any future model.

## Tracking gap (user-requested fix)

Forecast JSONs carry **no tournament field**, so MiniBench cohorts cannot be filtered locally. Each
biweekly MiniBench is its own tournament slug (`minibench-2026-06-29`), so cohort membership is
recoverable from the API retroactively. Fix: a `scores cohort <slug>` devtools command that fetches a
tournament's question list and produces this scorecard for any cohort. Optionally stamp the tournament
slug into the forecast output going forward.

   architecture/questions.
2. **Does the premortem ever move the number?** Instrument: log pre-premortem estimate vs
   post-premortem estimate across the corpus. Hypothesis: they're nearly identical (the gate is
   theater).
3. How much of the tail is inherent difficulty vs correctable? (44300 autopsy suggests even
   best-practice lands ~35–45% on a genuinely low-base-rate question.)
